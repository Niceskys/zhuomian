# E3-4B-1 round 2: transaction proof and bounded reader increment

PR [#38](https://github.com/Niceskys/zhuomian/pull/38) remains Draft. Reviewed baseline: dd6cf01bb6bb7b436cd696080bc6ce0c63194cb2. [ADR-0012](ADR/0012-independent-v2-storage.md) remains Proposed. This increment **does not close the independent merge gate**: damaged/missing authoritative root repair cannot yet prove complete reservation coverage.

## Changes and retained behavior

Current graph verification now checks every retained root witness against the verified segment chain. Newer witnesses detect stale root substitution; conflicting heads, foreign Workspace IDs, invalid selectors, checksummed future formats, corruption and non-file witnesses refuse. Missing/corrupt state still refuses before attempting fallback. All files are retained. v1 production, original 697 test bodies/assertions, default factory, legacy compatibility and frozen performance checks remain unchanged. PR #31–#33 remain independent and unused. No migration, cleanup, Apply, export, resource access or default switch is added.

The new exact owned-buffer reader removes the previous growing MemoryStream/copy and pooled 64 KiB clear per physical read. It retains the same native opens and every history validation. Full history still requires O(n) fresh page reads/decode and witness reads per operation; the 1024-save sequence remains quadratic aggregate work. No constant-time claim is made.

## Authority-loss proof and blocker

A pre-A crash leaves a complete raw dependency without an accepted reservation. A post-A/pre-B crash retains an old-root witness, while the new authoritative root may be the only evidence identifying the accepted branch. After losing that root, multiple raw branches can contain the same revision with different content; choosing one loses a possible commitment. Even a valid highest retained root does not prove that a later lost A did not exist. The retained witnesses are prior roots, not a complete independently anchored journal. Tests cover pre-A, post-A, post-B root loss/corruption, future root, mixed branches/IDs and missing/damaged pages; repeated Load, Save, Restore and Initialize refuse and preserve exact evidence bytes. **No writable root repair is implemented.** No trusted revision is reported when the authority cannot be established.

A valid older root with a newer extant witness now refuses. A deliberately substituted older valid root when the only newer A authority has also disappeared remains an unproved rollback case; it cannot be solved by claiming that filenames or a scalar high-water integer are authoritative. Engineering activation remains explicitly isolated. A reviewed new completeness protocol and transition/compatibility proof are required before closing P0.

## Executable fault matrix

`V2TransactionMatrixTests` has 81 deterministic cuts: Initialize/Save/RestoreRevision × three writes (page, reservation root, main root) × seven write stages, plus six dependency/A/B cuts per operation. Stages: before create, after create, halfway write, before Flush, after Flush, before readback, after readback; before/after segment publish; before/after A; before/after B. `V2KilledMatrixTests` executes the same 81 cuts in actual owned .NET children, kills each process, and uses a new child for Load. Original four killed-child tests remain. At every held cut competing Save and Restore must return Busy.

Each generated matrix JSON records disk families/counts/bytes at the cut, readable Workspace, trusted reserved revision when proven, writable/resume versus blocked state, and retained original evidence. Initialization before creation leaves only an empty lock and may accept a new explicit initialization; partially written or orphan-only initialization refuses. A root validly selecting zero permits only verified content retry despite Load being unavailable. Save/Restore cuts before A keep old main/floor, after A keep old main/new floor, after B load the new main. Identical retry resolves; conflicting accepted revision and lower revisions refuse. Main publication post-error is verified Committed when readable, Unknown when obstructed; existing native sharing/ACL/link/junction/rename tests remain. Three actual byte-mutation tests corrupt the page/A/B staging file between successful readback and publication: pages refuse before A, corrupt A/B authority returns Unknown and stays blocked; originals remain. Five additional native tests cover Initialize/Restore post-main read obstruction, real CreateFiles ACL denial with exact ACL restoration, and Restore sharing conflict/retry. Restore currently projects its internal StorageResult into RecoveryResult and does not expose CommitState.Unknown separately; this API observability gap remains open.

Coverage is not "every possible filesystem failure": injected Flush/I/O failures are deterministic seams; real ACL and sharing failures cover selected paths, not every instruction. Actual exhausted-volume disk-full, device flush failure, physical power loss, arbitrary filter behavior and every File.Replace partial-effect combination are uncompleted gates. A stopped child proves process-termination recovery on tested NTFS, not hardware power durability.

## Growth and consolidation review

At n distinct saves after explicit revision-0 initialization: n+1 page files, 2n+1 root witnesses, one state and one lock; total 3n+4 (1024 → 1025 pages, 2049 witnesses, 3076 files). Failed writes may additionally retain staging/orphans. File.Replace produces witnesses at A and B: predecessor main root at A, new reservation root at B. The reservation witness binds the new content/floor; earlier roots preserve provenance/failed-state evidence and can reveal rollback or conflicting branches. None is deleted or retired in this round. The current graph is sufficient for normal history traversal, but all extant witness contradictions are now checked.

Future bounded packs of immutable raw records could reduce future page-file growth, but need exact source hashes, record boundaries, previous-generation coverage, complete reservation/main selection proof, missing-source negatives and atomic publication under restart. Keeping originals and adding packs alone increases disk bytes/file count; claiming less physical storage would be false. Actually using packs as new authoritative dependencies requires a reviewed format transition and must not hide unknown/orphan/conflicting evidence. This is deferred rather than silently migrating or deleting files. Root publication still generates two witnesses per distinct save; eliminating them requires a proven alternate authority protocol, not calling File.Replace multi-file atomicity.

`v2-read-benchmark.json` records logical file bytes and native `FILE_STANDARD_INFO.AllocationSize` totals on Windows. Allocation covers file data allocation only; resident data may report zero and MFT, directories, indexes, journal and volume overhead are excluded. It is not total volume cost. Free-space changes on hosted runners include unrelated activity and cannot replace that measurement.

## Repeatable performance protocol

Build Release; set `E3_V2_EVIDENCE_DIR` to an owned evidence directory; run all tests. `V2ReadBenchmarkTests` creates history solely via real Initialize/Save calls (another 1024 distinct saves). At new/32/128/256/512/1024 it runs one full Load warmup per reader, then three paired rounds in AB/BA/AB order. A = original dd6cf01 PhysicalStorage physical reader; B = exact owned-buffer reader. **Both use the same strengthened round-2 graph/witness validation**, so this isolates reader cost, not the total baseline-versus-round-2 protocol change. It measures successful Save on generated clones, normal Load, logical Backup(Unchanged), RestoreRevision on clones, Unchanged Save and rejected conflicting Save separately. Copy/fixture construction is excluded. The benchmark collection disables parallel test interference.

Raw samples include elapsed/process CPU time, managed allocations, fresh logical read files/bytes, read elapsed and payload decode elapsed. Process CPU may have coarse resolution; logical reads are not physical device I/O. Digest/parsing/domain construction and native-open costs remain. Original capacity measurements continue unchanged, including 256/512/1000/1024, restart/restore/conflict checks. Compared with the prior run they include the added witness-validation work and runner variability, so a single before/after timing is not a calibrated latency claim. Persistence microbenchmark deviations from the product 60s/300s protocol are explicit; no UI frame metric/threshold acceptance is claimed.

## Reproduction and rollback

On Windows NTFS: `dotnet restore`, `dotnet build -c Release`, `dotnet format --verify-no-changes`, `dotnet test -c Release --no-build --logger trx`. CI runs these plus unchanged native v1, executable legacy compatibility and all six frozen A/B/C performance rounds. The v2 collector rejects missing matrix/capacity/performance evidence, failed or skipped tests. Artifacts contain generated metrics only, no personal Workspace bytes or private paths.

Rollback reverts this code increment while retaining every v1/v2 file. Format and A/B commit points remain version 2; the original reader can parse the same graph but loses the stricter witness conflict checks. Rollback is not a recommendation to write an uncertain store. Never reconstruct v1, republish old roots, delete reservations or redirect default clients as a rollback step. Missing-root recovery, exhaustive native filesystem failure coverage, actual disk-full/device evidence and the new authority/packing proof remain open. ADR Proposed; PR Draft; no merge or product-release recommendation.
