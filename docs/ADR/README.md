# Architecture Decision Records

Create an ADR for changes to Desktop Hosting, UI framework, rendering/backdrop, persistence, packaging, updates, discovery, plugins or media pipeline.

## Lifecycle

- **Proposed**: open for evidence and review.
- **Accepted**: approved and binding.
- **Rejected**: evaluated but not selected.
- **Superseded**: replaced by a newer ADR; never rewrite history.

Use four-digit sequential names such as `0001-desktop-host-strategy.md` and start from [TEMPLATE.md](TEMPLATE.md).
