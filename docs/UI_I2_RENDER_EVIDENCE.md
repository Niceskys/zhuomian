## Ownership and incremental implementation

The existing coordinator/HostLease still owns one formal visual HwndSource, one native foreground hook/session registration, WorkAreaGuard, native input, Z-order, frame/deadline timers and exception rollback. Renderer owns only its root, cached chrome/items, frozen brushes, source hook and Dispatcher exception subscription; the thread owns Dispatcher. No second Window/Application/desktop host/foreground authority is introduced. Existing framework-owned Dispatcher/composition infrastructure remains outside application host ownership.

Each Space owns cached background/title/search/toolbar/Back/Exit and an Item dictionary keyed by stable identity. Composite Space/Item keys allow future shared references. Idle chrome is collapsed. Items temporarily omitted by layout capacity remain collapsed while present in SceneSpace.ItemIdentities; actual removal releases references. No invisible duplicate IDs or reordering on hover. SceneLayout is immutable scene data with configurable padding/pitch/content origins and item extents (engineering defaults preserved); Capture owns all resulting hit rectangles and carries the layout data to WPF; WPF uses snapshot rectangles with the existing rounded physical edges. PresentationTheme centralizes border/radius/icon/font/state presentation and a future transform-only hover parameter. Resolved palette remains scene data. Changed geometry/content/visibility explicitly invalidates root measure/arrange to avoid retaining a larger old arrange slot when a cached card shrinks on reversal; unchanged scenes do not request that invalidation. The 500-sequence geometry test caught this during Windows validation. No settings, real hover interaction, theme editor, search/IME or plugin binding is enabled.

Default cards remain Work 320×200/8, Study 260×180/6, Play 380×240/12. Idle has title/multiple icons, no visible search/tools. Expanded has Header/Search/Toolbar/Content/Back/Exit. Capacity can temporarily show fewer icons during early expansion as in UI-I1; the complete 26 identities remain cached, avoiding churn. Icon pitch/padding/rounding are unchanged.

Diagnostic definitions: VisualCreated/Reused/Removed count explicitly owned FrameworkElements (including icon/glyph/label and search child), not WPF internal template/GPU objects. LiveVisuals is the retained count. FullTreeRebuild counts initial population and population after Reset, not ordinary frames. LayoutInvalidated counts element geometry changes, not WPF internal layout passes. FrameUpdateTicks/ManagedAllocation cover synchronous Submit on the owner thread. External benchmark samples also include call overhead. Brushes are frozen and only replaced on palette changes; no unbounded brush/bitmap cache exists.

## First-down investigation and protection

Previously first-down read the most recently submitted scene directly. Old/new layouts may put different Item IDs, blank, Back or Exit under the same pixel. WPF rendering is asynchronous and high load can increase the gap. Region is updated before Submit; UpdateLayout does not acknowledge presentation. Offscreen PNG does not acknowledge presentation either.

SceneInputGuard observes successfully submitted scenes after Submit, retaining at most 32 distinct hit geometries with supersession timestamps. It compares all candidate SurfaceHits at first native Down, checks current generation and monotonically increasing FrameId, and rejects incomplete coverage after overflow. Repeated static submissions occupy one entry. A superseded geometry remains a candidate for 250ms after replacement, even after a long static interval. Older history expires lazily during submit/press: no idle expiry timer. Reversals retain intermediate candidates rather than resurrecting an old hit. Reduced Motion jumps undergo the same checks. A new generation rejects stale history until it expires; HostLost clears history and visuals immediately. Failed submission never becomes a new history entry.

Conflict/generation/coverage cancellation consumes Up/DoubleClick while the rejected native sequence remains inside the host. MouseLeave and CancelMode reset the rejection latch and guard pin; a delayed Up after that reset cannot launch because E1 has no pressed gesture. Accepted Down enters the original dispatcher GestureId path, pins identity and submitted picture, pauses animation; native drag-threshold cancellation clears the guard pin as well, and later availability/generation/cancel/leave rejects Up as before. Counters Attempts/Accepted/Conflicts/GenerationRejected/CoverageRejected/Evicted describe cancellation frequency; native smoke logs actual sample counts. These small adversarial fixtures are not population UX statistics. Conflicting moving targets may require another click after stabilization (up to the engineering lag window); unchanged targets remain clickable while other content moves. No global input injection is used: messages target only the process-owned hidden HWND.

**PresentedFrame remains UNKNOWN / UNVERIFIED.** A display delayed beyond 250ms can show an evicted picture, including after a Reduced Motion jump or generation reset. This implementation proves identity consensus within retained submitted candidates, not arbitrary real-screen identity correctness. 250ms is not a measured latency bound. Physical first-down under high CPU/GPU load, rapid reversals, occlusion/session transitions and display timing still require attended Windows 11 tracing before real resources/product acceptance. No false PresentedFrame or GPU/dropped-frame measurements are generated.

Synthetic DPI is not mixed-DPI hardware support.

Structural expectation: UI-I1 creates 110 owned elements on each Idle Submit (115 with one expanded toolbar and all 26 visible Items; early capacity may reduce that). UI-I2 creates 125 once (all chrome, 26 Items), then **0 new owned elements per ordinary replay frame**, including temporary capacity changes and reversals. One Item label edit creates 0; adding one creates 4; removing it removes 4. Actual tests assert these counts and retained 125 after every ordinary frame, 0 after reset/dispose/fault. New managed allocations still include scene processing/LINQ/WPF layout; zero element creation is not zero allocation. Raw before/after medians/totals must be read from the actual CI artifact, not guessed here.

This is a deliberately shortened Windows CI engineering protocol, not PERFORMANCE_BUDGET S1–S8 calibration (no 60s warmup/300s hardware measurements). Baseline first order, shared process/JIT/GC noise and hidden rendering limit timing comparisons. No GPU scheduling, input-to-photon, displayed frames, 60FPS, dropped frames, long residence or product memory budget claim. Diagnostics are not eligibleForThresholdCalibration. Native motion smoke retains no idle animation/deadline timer; renderer adds no timer/thread/render-event loop.
